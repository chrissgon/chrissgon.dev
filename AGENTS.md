# chrissgon.dev

Christopher Gonçalves's personal site: static Astro pages in EN (at the root) and PT (under /pt/), plus `llms.txt` and schema.org JSON-LD for AI agents, all generated from one typed data module. Status: design direction A "Estrutura à mostra" (see `README.md`).

## Architecture

The design and its decision records are kept locally by the owner, outside this repository (`docs/` is git-ignored). What holds here:

- `src/data/` is the only source of facts (profile, products, projects, posts, trajectory, lab, stats, labels). `src/data/index.ts` validates everything with the zod schemas in `src/data/schema.ts`; pages, `src/lib/llms.ts` and `src/lib/jsonld.ts` import from it and never hard-code a fact.
- Static output, no adapter (`astro.config.mjs`); i18n with EN unprefixed and PT under /pt/; `site` comes from the `URL` environment variable, else `https://chrissgon.dev`.
- One view per page in `src/views/`, used by the EN page in `src/pages/` and the PT page in `src/pages/pt/`.
- Text endpoints: `src/pages/llms.txt.ts`, `src/pages/pt/llms.txt.ts`, `src/pages/robots.txt.ts`. Sitemap: `@astrojs/sitemap`.
- Read-only MCP server: `netlify/functions/mcp.mts` at `/api/mcp` (route and rate limit in its `config`), tools in `src/mcp/server.ts`, reading only `src/data/`. Every tool stays read-only with a strict input schema; `tests/mcp.test.ts` covers the protocol, each tool, unknown data (EDGE-1) and injected instructions (EDGE-3). Local run: `netlify dev --offline --framework '#static' --dir dist` after `npm run build` (`astro dev` does not serve functions).
- Netlify builds and publishes (`netlify.toml`); this repository's CI never deploys.
- The portrait island (`src/components/Portrait.astro`) mounts `src/lib/portrait/` on a canvas: pure parts (`levels.ts`, `grid.ts`, `gating.ts`, `colors.ts`, `bands.ts`) are unit-tested, `mount.ts` holds the DOM. Clips are offered only when their files exist in `public/portrait/` at build time. The pointer push and its spring (`push.ts`) are shared with the background dots.
- The background dots step aside from the pointer like the portrait's (`src/lib/griddots/`): the CSS grid on `body` stays the picture (first paint, no JavaScript, reduced motion, touch, Save-Data); with a mouse or pen, `src/scripts/site.ts` imports the effect as a lazy chunk once the page is idle after load, outside the first render. It adds one layer to the body (`.grid-dots`: the body's box, z-index -1 inside the body's own stacking context, so behind every piece of content, `overflow: clip`, no pointer events) holding a viewport-sized canvas on grid lines; a frame covers only the dots it moves with the page's background colour and draws them where the push puts them, pixel for pixel like the CSS dots (`geometry.ts`, unit-tested). An empty canvas at rest, no frame while the pointer is still or the tab is hidden. Dots the portrait draws itself are left to it (its canvas carries `data-grid-owner` and `ownsGridDot`), and so are dots under an opaque box.
- Design direction A, refined by the owner's Claude Design home (2026-09-30): `src/styles/site.css` (frame, cells, corner markers, captions and numbered indexes, filter chips, the view-as-agent rules) plus one component per repeated piece in `src/components/` (`Cell`, `AgentSwitch`, `AgentText`, `Showcase`, `CopyField`, `CodeLines`, cards). Code never scrolls sideways: it wraps (`white-space: pre-wrap`, `overflow-wrap: anywhere`), each line of a snippet a block with a hanging indent and `<wbr>` inside URLs and after JSON commas (`src/lib/code.ts`, `CodeLines`, `src/scripts/code-lines.ts`); a text to copy is a wrapping read-only textbox (`CopyField`), never a `readonly` input. The project filters (`src/scripts/filters.ts` over `src/lib/filters.ts`) run on the projects page and in the home page's projects section. Colours are Perfect UI's dark tokens only, one blue element per viewport, no gradients or shadows (the radial-gradient images are dot patterns). "view as agent" is CSS only (`[data-agent-scope]:has(.agent-toggle:checked)`), with the switch in every page's header and the body as the page's scope; each region's reading is its part of llms.txt (`llmsParts` in `src/lib/llms.ts`), and whatever is not the reading or the frame carries `.human`. A scope inside another (the lab's view-as-agent experiment) reacts only to its own switch: the page's rules exclude nested scopes (see the comment in `site.css`), so neither switch swaps the other's scope. Small enhancements live in `src/scripts/site.ts` (tabs, copy, reveal on scroll, count-up) and `src/scripts/filters.ts`, and everything reads and works without JavaScript.
- Post covers are 4:5 portraits cropped at build (`src/components/PostCard.astro`): `src/lib/covers.ts` gives the largest 4:5 crop a source holds and srcset widths never above it (the image service does not enlarge); each post's `coverFocus` in `src/data/posts.json` anchors the crop. The home page's posts row scrolls sideways below 1024 px; the writing page is a grid of 4, 3 or 2 columns.
- Logo 4a: the favicons and `site.webmanifest` in `public/` (linked from `Base.astro`, at stable paths), the symbol inline in the header's brand link (symbol alone when the header row, which also holds the agent switch on every page, leaves the brand less room than the domain needs: a container query on `.brand`; the domain stays the accessible name; below 900 px the header has two rows), and the share images `public/og/og-{en,pt}.png` drawn by `scripts/og-image.ts` (`og:*` and `twitter:*` tags from `src/lib/og.ts`). Only the files the site uses come from the owner's export, with its C2PA metadata stripped (SVG `<metadata>`, PNG `caBX`); the JSON-LD Person carries no image.
- Fonts come from Astro's Fonts API (`fonts` in `astro.config.mjs`, `<Font>` in `src/layouts/Base.astro`); never add a third-party font link.

## Conventions

- TypeScript strict (`tsconfig.json` extends Astro's strict preset, plus `noUncheckedIndexedAccess`).
- Texts shown on the site are copied verbatim from the owner's approved content. Never write, translate or "improve" a public text on your own; a missing text is an open question for the owner. Labels not yet approved live in the `provisional` block of `src/data/labels.ts`.
- Nothing about employers, clients, family, age, income, politics, exact location, leadership or job seeking goes into any file. The sensitive-topics check enforces the keyword part; a false positive goes to `src/data/sensitive-exclude.json` with a reason, never by editing `src/data/sensitive-topics.json`.
- Code, comments and repository documents are in English.
- Commits: Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`), signed.

## Testing

- vitest; tests live in `tests/`. Cover the data schemas, the sensitive-topics check, the generated `llms.txt`, JSON-LD and project cards, the MCP tools, the cover crop (`src/lib/covers.ts`), the build checks (`check-images`, `check-dist`, the Lighthouse gate) and the pure portrait functions (`src/lib/portrait/`) whenever they change.
- Images committed under `src/assets/` and `public/` carry no EXIF, GPS, XMP, text or C2PA (`caBX`) metadata, SVGs in `public/` no `<metadata>` element, and the share images stay 1200 x 630 and under 100 KB (`tests/images.test.ts`).
- `check-dist` also fails when a page lacks a favicon link (`favicon.ico`, `favicon.svg`, `apple-touch-icon`, manifest), `og:image` or `twitter:image`, or one points to a file missing from `dist/`; when `og:image` is not an absolute URL on the site's origin, not a PNG of its declared size or has no alt; when the manifest lacks a name, short name, start URL or an existing icon; when an SVG file or inline SVG in `dist/` carries `<metadata>`; and when `netlify.toml` does not serve `/site.webmanifest` as `application/manifest+json`.
- `npm run check:portrait` (Playwright) checks the built home pages: canvas drawn, no video request without clips, with reduced motion or Save-Data, no console errors, no-JS fallback, the pointer pushing dots and the poster coming back exactly, the portrait staying whole until a third of its box has scrolled away and back on the grid once it has gone; at 375 px on touch, the portrait starting behind the hero text with no line between them and every link and button of the text taking the tap; when the build carries the real clips (`public/portrait/portrait-loop.*`), the video path and no long task while the clip plays at CPU x8, with the pointer check run under Save-Data; `-- --with-synthetic-clips` adds the same video checks on synthetic clips (loop and greeting). Run it after changing the portrait or the layout around it.
- `npm run check:griddots` (Playwright) checks the background dots on every page, EN and PT, at the top and lower down: the layer behind the content, the pointer moving the dots near it, a dot drawn in place lighting the same pixels as the CSS grid (pixel ratios 2, 1 and 1.5), the plain grid back within 1 s with an empty canvas, no frame requested while the pointer rests or once settled, no horizontal scroll, no layout shift, the portrait's dots left to it, a scroll under a still pointer, a hidden tab, and nothing loaded with reduced motion or on a touch phone. Run it after changing the grid, the portrait or the background.
- `npm run check:layout` (Playwright, also in CI's `build` job on the runner's Chrome) loads every page, EN and PT, as loaded, with the header's "view as agent" on, with each lab experiment opened (switch off and on), with the view-as-agent experiment's own switch on alone, and through the projects filters and back, at 320, 360, 375, 390, 414, 600, 768, 820, 1024, 1100, 1186, 1280, 1366, 1440 and 1920 px with scrollbars drawn, and fails when the page is wider than the viewport, naming the elements that stick out, or when any code element (`pre`, `code`, `kbd`, `samp`, `output`, a read-only input, a code class) or the eval table is wider than its own box. Code and tables wrap; only chip rows, tab lists and the posts row may scroll inside their own box; never hide the page's overflow to pass it. It also fails when a grid of bordered cells (`.cells` in `src/styles/site.css`: the home numbers, products and lab rows, the lab page's row, the writing sheet) leaves a cell's right or bottom line (along the whole height of its row, so a divider cannot stop short of the lines above or below it), or one of the grid's own edges, missing or doubled, as loaded and with its last cells hidden so every incomplete last row is seen. Such a grid uses `.cells` (each cell owns its right and bottom lines), never per-breakpoint `nth-child` border rules. With "view as agent" on it fails when anything in a switched-on scope other than the reading (`.agent-text`) and the frame (cell tags, corner markers, site header and footer, the switch) draws text, or when a heading there is drawn taller than 1 px or is missing from the accessibility tree: titles and numbered indexes are hidden the `.sr-only` way, never removed. Every state also checks that exactly the expected scopes are on and that a scope that is off shows none of its readings (the lab's two scopes stay apart), that the header's pieces (symbol, domain, links, switch, EN / PT) never overlap or leave the viewport, and, on the projects page, that the reading lists every project whatever the filters and that switching back restores the filtered cards and the pressed chip.
- Never commit a source photo or source video of the owner: only the dot grid, the fallback WebP and the encoded clips.

## Security

- Credentials never enter the repository. `.env` and `.env.*` are git-ignored; private sensitive terms come from `SENSITIVE_PRIVATE_TERMS` or the local, git-ignored file docs/private-terms.txt.
- Enable the pre-commit hook once per clone: `git config core.hooksPath .githooks`. It runs the secret scan, types, tests and the build. Never skip it.
- Report vulnerabilities as described in `SECURITY.md`.

## Working rules

- `main` is protected: every change goes through a branch and a pull request, merged by squash only when the required checks `secrets`, `build` and `lighthouse` are green. No force push, no rule changes, no bypass.
- Nothing is published outside GitHub from this repository by an agent: Netlify and DNS changes are the owner's.
